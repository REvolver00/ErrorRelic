# ERROR Relics 联机与说明显示

基线：84455be；本次版本：0.91.3（联机预览）。开发与验证使用游戏 v0.111.0、BaseLib 3.4.7。

## 行为

- 每名玩家由自己的 ERROR 凭证启用模式，独立持有 1H + 1E 遗物。
- E002 / E007 继续排除在随机池之外，保留原实现和编号。所有枚举值、特别是 E009 / E010 的历史顺序保持不变。
- 联机生成使用游戏的内容随机数构造器，结合对局种子、玩家位置、原遗物 ID、楼层和来源标识。不会消耗战斗或奖励的共享随机序列。同一来源重新构建预览时得到相同组合。单机维持原随机池与生成方式。
- H/E、组合锁定标记、原图路径和持久计数沿用原版 SavedProperty 保存与网络传输。恢复到玩家背包时由原版重新绑定持有人，不在恢复时重新生成组合。
- 战斗开始时统一清空临时战斗计数，保留跨战斗计数。
- 商店、奖励、先古和事件仍在各自来源的最终阶段替换；不增加全局遗物工厂转换。
- 多人宝箱先保持原版选项、投票、争抢和补偿分配，再根据实际获奖者生成可变 ERROR。未开启模式的玩家照常获得原遗物。投票阶段展示原遗物，获得后显示 ERROR 完整效果。单机宝箱流程保留。
- 事件取得遗物的保护不再依赖调用栈是否被运行时优化掉；原版泛型调用收到类型兼容的返回对象，背包中实际加入 ERROR。

## 效果说明

主悬停说明和事件遗物说明显示当前实例的完整中文“触发条件，效果。”，下一行保留 Hxxx-Exxx 供反馈。

例如：

```text
你的回合开始时，获得 300 金币。
(H002-E004)
```

本地化表仅存放 `{ErrorDescription}` 模板，显示时填入该遗物自己的文本。两件同模型 ID 的 ERROR 不会互相覆盖说明。尚未生成组合的预览显示待生成提示。卡牌和附魔名从游戏本地化表读取；中文后备译名来自 v0.111.0 的原版文本。数字、关键词、附魔和回复量沿用原版高亮，能量使用原版图标。

## 构建与检查

在 Windows PowerShell 执行：

```powershell
./tools/test.ps1 -GamePath '你的 Slay the Spire 2 目录'
```

测试程序独立发布为与游戏对应的 .NET 9 运行时；不把系统 .NET 10 的补丁兼容性当作游戏结果。使用真实游戏 DLL 和网络读写器检查组合数据往返、持有人绑定、计数重置、说明隔离、随机池及补丁匹配。控制台测试仅屏蔽依赖原生 Godot 的初始化日志，不替换保存/网络编码逻辑。

仅编译，不写入游戏 mods 或自动更新依赖清单：

```powershell
dotnet build ErrorRelics.csproj -c Release -p:DeployModOnBuild=false -p:UpdateDependencyManifest=false
```

资源文件可使用 `tools/pack-assets.gd` 打包；只处理本项目图像和本地化文件，不包含游戏资产。原 PNG 路径通过 Godot remap 指向打包后的纹理资源。

## 本机双端测试

`tests/MultiplayerSmokeDriver.cs` 是单独的测试模组，不包含在正式 ErrorRelics DLL 中。需要独立的游戏运行目录和存档目录；测试标记为 `.errorrelic-test-runtime`，用户目录为 `ErrorRelics-MultiplayerTests`。不得用正式游戏存档运行自动驱动。

用 PowerShell 7 执行 `tools/prepare-smoke.ps1 -GamePath <游戏目录> -BaseLibPath <BaseLib文件目录>` 准备隔离运行目录。先运行一次 `tools/test.ps1` 恢复构建依赖，然后可使用 `tools/start-smoke.ps1 -RuntimePath <隔离运行目录>`。此脚本仅停止该目录下的旧测试进程，先静音全部测试音量，再以无窗口、Dummy 音频驱动启动主机和客户端。FMOD 不一定遵循 Godot 的 Dummy 驱动，因此音量必须同时设为零。

驱动通过原版大厅与战斗同步流程检查玩家各自持有不同组合、进入战斗后简单效果按持有人结算、说明正确以及跨战斗恢复。控制台自动检查不能替代真实网络测试；本机双端也不能替代所有组合、四人、跨系统和长局验收。

## 本次验证结果

- Debug / Release 均编译通过；保留的 31 条编译警告来自原有可空性和未等待的视觉任务。
- Release 控制台检查：43,983 次断言通过，包含全部 3,965 组说明文本与真实网络遗物数据往返。
- 静音、隔离存档的本机主机/客户端：成功加载 BaseLib、ErrorRelics 和独立测试驱动，连接并开始跑局。
- 两名玩家分别持有 H002-E004（每回合金币）和 H002-E033（每回合最大生命值），连续三场测试战斗按各自持有人结算一次。包含两件同模型不同组合的遗物说明检查。
- 两人分别选择宝箱选项，获得的 ERROR 稀有度、组合、持有人均正确，并通过下一场战斗的数据重建。此项用测试驱动固定宝箱组合 H002-E001，排除选牌 UI 干扰；正式代码仍使用随机生成。
- 第三场战斗验证宝箱遗物各自赋予 1 力量；两端对每个玩家调用正式生成器所得的 H/E 完全一致。
- 本机双端为 ENet、无窗口测试；不代表已遍历全部游戏组合、四人、Steam 跨机器、断线恢复或长局。无窗口模式出现原版 Dummy 纹理警告，快速调试跳房可能出现地图涂画消息的接收时序日志；未作为画面布局验收。
- 最终测试原始记录在本机 `.godot/test-evidence/multiplayer-host.log`、`multiplayer-client.log`，不随发布包分发。

## 0.91.2 单人宝箱诊断

用户报告首个宝箱未收到遗物，精英奖励正常。读取该局存档：第一次宝箱没有 relic_choices 领取记录，后两次宝箱存在 was_picked=true。不能据此判定玩家操作或其他模组造成，也未确认单人宝箱普遍失效。

新增真正的 Singleplayer 模式测试入口 `--errorrelic-single-smoke`（不用 fastmp）。相同 H061-E033 组合通过宝箱领取信号测试，遗物入包、稀有度保持，并在下一场战斗将最大生命值从80增到100；不是实际鼠标命中的复现。测试保持静音与独立存档。

本版未改动宝箱发奖逻辑，只添加针对 ERROR 宝箱的展示、点击接收、跳过日志，以及 ERROR 进入背包的确认日志。若故障再次发生，应保留现场并对照上述日志定位，避免自动发奖等改变正常跳过行为的猜测性修复。

## 0.91.3 完整效果显示开关

在 BaseLib 的“模组配置 → ErrorRelics”中提供“显示完整效果”，默认开启，选择会保存到本机 mod_configs/ErrorRelics.cfg。
关闭时，ERROR 遗物的主说明、事件说明及 H/E 编号均隐藏，固定测试 ERROR 的效果/风味编号也隐藏；名称与图标保留。重新悬停时按当前设置生成说明。该设置不进入存档或联机数据，也不控制任何触发/效果逻辑。

静音的原生游戏测试验证了配置页确实生成复选框、中文标签、默认开启、关闭/重开、配置保存/重新读取、隐藏主说明/事件说明/风味编号、保留原版遗物说明，以及遗物保存字段不受影响。测试入口为独立测试模组参数 --errorrelic-config-smoke，不启动跑局。
本版增加设置本地化和空说明资源，升级时必须同时更新 DLL、JSON、PCK，不能只替换 DLL。
## 0.92.3 联机、进店附魔与 SL 修复

这三项分别处理：

- 联机开局：每端都会模拟所有玩家的涅奥事件，原先直接读取本机“开局直接获得红镐子”设置，可能对同一玩家生成不同遗物和选项。现在通过原版 PlayerChoiceSynchronizer 同步每位持有人的选择；不同玩家仍可以使用不同设置。
- 联机效果随机数：变化、诅咒、随机升级使用每件 ERROR 的独立随机流，执行序号由 SavedProperty 保存。异步选牌不再消费其他玩家效果共用的 Niche 序列。战斗随机数与原版选牌同步接口沿用原流程。
- 进店附魔：王室认证及 E102–E105 在选牌返回后复核持有人、牌组位置和附魔资格，避免对等待期间已经改变的目标再次附魔。E012 对原版附魔动画的空返回值做检查，远端不再把空节点传给 UI。王室认证去掉最终会被选牌接口恢复牌组顺序的无效洗牌。
- SL：单人也使用对局种子、玩家位置、楼层、原遗物 ID 和来源生成组合；单人宝箱采用同一路径。同一来源重建保持相同 H/E。已有背包组合继续按保存值恢复，效果随机流的执行序号同时保存。

验证：Debug / Release 构建通过；控制台 62,698 次断言通过，新增 JSON 保存与真实网络数据的执行序号往返检查。隔离存档的双端测试中，主机开启、客户端关闭自动红镐子，两端均确认玩家各自设置并进入第一场战斗出牌阶段；H029-E009、H029-E012 均在两端完成，选中卡牌、附魔结果、来源组合及独立随机流输出一致。单人 H029-E011 自动附魔另行检查。

这些测试没有复现反馈中的原始偶发进店崩溃；本版针对已发现的附魔调用风险修正，尚不能据此认定所有附魔组合均无故障。双端测试使用本机 ENet、游戏 v0.111.0；测试驱动、日志及测试存档不进入发布包。Steam 上传仍须逐版本审批。

测试入口为独立测试模组：`--errorrelic-merchant-smoke`，默认 H029-E009；`--auto-enchant` 检查 E011，`--goopy` 检查 E012。双端另加 `--merchant-mp` 与原版 fastmp 参数；`--first-battle` 检查开局设置不一致的首战路径（主机加 `--pickaxe-on`，客户端不加）。仅使用 `tools/prepare-smoke.ps1` 创建的隔离运行目录与静音测试存档。

## 0.92.4 入战奖励黑屏修复

H025-E106 在进入战斗房时同步提供星盘的 5 次卡牌奖励。原版战斗房会等待入房 Hook 完成，随后才更新房间消息缓冲位置和解除转场，产生两处循环等待：

- 奖励界面等待玩家操作，但转场黑幕仍遮挡界面并拦截输入。原生单机测试复现了 `InTransition=True / alpha=1 / MouseFilter=Stop`。
- 只解除黑幕仍不足以修复联机：远端收到奖励完成消息时，消息缓冲还停在旧房间，将新房间消息排队；入房 Hook 又在等待这条消息才能返回。双端测试复现了主机进入出牌阶段、客户端卡在奖励同步的状态。

E098、E099、E106、E107、E108 共用奖励界面入口：先通过原版接口把消息缓冲位置对齐到当前房间，再按需解除转场，最后等待原版 `RewardsCmd.OfferCustom` 完成。不跳过效果、不减少奖励、不延迟到下一回合或下一场战斗；持有人、奖励生成和网络同步继续沿用原版实现。

回归入口：在准备好的隔离运行目录执行 `tools/test-room-rewards.ps1 -RuntimePath <隔离运行目录>`。驱动固定 H025-E106、普通速度与真实黑幕转场，依次检查单机、主机持有和客户端持有；验证本机持有人看到 5 次卡牌奖励且没有黑幕拦截，通过原版跳过按钮完成奖励后，各端进入出牌阶段，效果只执行一次。联机检查从当前背包读取战斗同步后的遗物实例，避免误读已被原版重建替换的旧引用。仅使用独立测试存档，无窗口、静音运行；不是四人 Steam 跨机器验收。

验证结果：Debug / Release 编译通过，控制台 62,698 次断言通过。单机、主机持有的双端和客户端持有的双端均通过：奖励界面 `InTransition=False / alpha=0 / MouseFilter=Ignore`，远端完成奖励同步，双方进入出牌阶段，每端当前背包中的遗物执行次数均为 1。本次未测试实际领取卡牌、全部奖励效果或四人 Steam 长局。
