Implementation notes
- New overrides live in separate partial files:
  ErrorRelicsCode/Relics/ErrorGeneratedRelic.Hooks105.cs (H105-H137) and
  ErrorGeneratedRelic.Hooks138.cs / .Hooks143.cs / .Hooks148.cs (H138-H150). The main
  relic file only changed its class declaration to partial.
- Every override early-returns unless the relic's own HookId matches,
  so one relic never claims another fragment's hook.
- Galactic Dust keeps a saved star counter and preserves the remainder;
  a single spend can cross several thresholds.
- Metronome's orb counter is cleared in BeforeCombatStartLate, matching
  the vanilla reset points.
- E112 generalizes the vulnerable target to a random enemy because H and
  E are independent fragments; the amount stays at the vanilla 2.
- E129/E130/E131 are deliberately NOT listed in the crash blacklist:
  AfterCombatVictory fires after the combat is over, so gating them on
  CombatManager.IsInProgress would silently disable them.
- RequiresActiveCombat was renamed to WouldCrashOutsideCombat and reduced
  to a blacklist: only effects that provably read a null CombatState or
  an empty combat pile outside combat are listed. A NOOP result is
  correct behaviour; the only hard rule is that the game must not crash.
- No deferred replay was added: combat-only effects still silently skip
  when triggered outside combat.
- Combination blacklist (ErrorRelicsCode/Fragments/ErrorFragmentBlacklist.cs):
  checked per hook+effect pair before execution, so a dangerous pairing is
  skipped without touching the effect itself. Live testing showed that
  H141_AfterBlockGained combined with any block-granting effect, and
  H150_AfterCurrentHpChanged combined with any heal/max-HP effect, feed
  themselves forever and soft-lock the run; those 17 pairs are blocked.
- H144_AfterCardEnteredCombat was removed entirely (user decision): the
  trigger fires while combat is still initialising, which players cannot
  read, and it produced a crash with E109 when the selector was not ready
  yet. The enum slot is kept as H144_ReservedCardEnteredCombat so later
  hook values do not shift under existing saves; it is excluded from
  generation, has no override, and its combination-blacklist entry and the
  E109 isolation entry are gone with it.
- H142_AfterDamageGiven x damage effects is still under observation: it
  chains hard enough to nearly wipe an encounter, but no unbounded loop has
  been confirmed yet, so it stays out of the blacklist.

Text and bookkeeping
- Hooks[]/Effects[] in ErrorDescriptionText are extended in Chinese with
  indices kept strictly aligned to the enum values; the removed slot now
  reads as a cancelled fragment.
- English hook/effect text in ErrorHookRegistry and ErrorEffectRegistry.
- Error Proof description and the test reachability assertion now use
  149 active hooks and 142 active effects (E002 and E007 stay excluded from
  the random pool).
