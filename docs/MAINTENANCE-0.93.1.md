# ERROR Relics 0.93.1 维护修复

基于 GitHub main eefa5e9（0.93.0），使用本机游戏 v0.111.0、BaseLib 3.4.7 验证。

## 改动

- 描述不再通过读取 Owner 判断 canonical 遗物是否已生成；标题单独填充 ErrorTitle，关闭效果说明不会隐藏乱码标题。地图历史读标题不会执行实例描述。
- 单人宝箱使用独立 mutable 预览，在原版发奖克隆边界直接发放该实例；不再把组合、来源美术或生成标识写入 ModelDb 共享模板。多人保持原版投票与分配。
- 任意玩家真实获得 Proof 后，本局永久激活 ERROR。覆盖普通获得与直接 AddRelicInternal；建局/载档及首次查询补查真实库存。创建预览不会激活，移除 Proof 不关闭。开局是否给予 Proof 仍采用各玩家同步后的偏好。
- 激活状态通过 BaseLib run 扩展保存；事件、奖励与宝箱的生成序号按玩家保存。生成 identity 与已锁定 H/E 通过 SavedProperty 同步。已填充的额外遗物奖励保存完整模型，恢复/重复 Populate 不重抽。
- 商店使用原版已执行的 Shops RNG 计数区分槽位及补货，不额外抽游戏 RNG，也不推进共享生成序号。商店本地补货不会改变后续同步事件的组合。
- Circlet 可重复作为来源外壳，每次新生成取得新 identity；随机抽样仍允许偶然抽到相同 H/E，不承诺穷尽组合前不重复。
- 原版 SFX 从 222 项收紧至 106 项。审查 FMOD one-shot、持续点、参数；211 个候选进行静音实播，只保留本次采样中 2.5 秒内自然结束的事件。详细数据见 SFX-AUDIT-0.93.1.json。
- ERROR 自己创建并持有原版声音实例，每个实例最长播放三秒真实时间，场景切换时释放。短声音仍可叠加；不会停止游戏创建的其他实例。播放前再次拒绝不存在、非 one-shot 或有持续点的事件。随机音频变体可能比采样更长，因此保留运行时上限。
- 新 ERROR 声音会停止此前的 ERROR 自定义声音；不停止游戏全局音频。
- 游戏 NSceneContainer 切换前恢复旋转和 pivot；运行时入树前的拾取延后到 Ready 后。维持原有 TextureRect 候选范围及输入保护。
- 载档新增成对阶段日志（开始/完成/异常）和载档期间的 H/E 执行日志。异常原样继续传播，不用空 catch 隐藏失败。

## 验证

- Debug / Release 构建通过，0 错误，40 条编译警告。
- 控制台回归：62,702 次断言通过，包括新增的 canonical 描述、标题与 generation identity 网络往返。
- 隔离、静音的真实游戏内维护测试：105 次检查通过，覆盖无 Proof 的永久激活存档/网络恢复、连续 40 个 Circlet 的双状态确定性、商店补货隔离、已填充奖励恢复、旋转复原、声音实例超时且不停止独立循环实例，以及真实 NGame.LoadRun。
- 单人原生宝箱回归通过：实际发出点击信号、领取独立 mutable 预览并进入第三场战斗。
- 本机 Host/Client 双端冒烟通过：三场战斗、宝箱投票/发奖、每人独立效果；双方移除 Proof 后仍启用 ERROR；两名玩家各连续生成 8 个 Circlet，16 组 identity 与 H/E 在两端逐条一致。首轮主机资源预载退出、客户端超时；分开启动重试后通过。
- 音频审查：222 个候选中 3 个不存在；5 个确定为循环事件；其余按参数和实际结束时间筛选，最终保留 106 个。时长字段为 0 的事件未被当作零时长处理。

## 尚未证实解决的问题

- 用户报告的偶发载档卡死未保留故障日志。本次修复了实际可达的 canonical 异常，但不能据此宣称原卡死根因已确认或所有卡死都已解决。下次复现应保留 ERROR load begin/end/effect 日志及完整游戏日志。
- 旧档若已经失去 Proof 且从未保存激活标记，无法可靠推断曾经激活；仍持有 Proof 的旧档会自动补齐。
- 其他 Mod 如果只在某个客户端修改库存却不使用任何原版同步机制，本 Mod 的状态保存不能替它完成网络同步。
- 自动测试不覆盖全部 11,336 个 H/E 组合、四人、跨系统和长局。headless 测试日志存在引擎预载与退出时资源警告，未据此宣称日志完全无错。
