ERROR Relics 0.90 Beta - EVENT3 compatibility test
=====================================================

Why EVENT3 exists
-----------------
EVENT2 exposed a concrete vanilla API constraint:

RelicCmd.Obtain<T>(Player) internally awaits the final RelicCmd.Obtain(...)
and casts its result back to T.

If the final Obtain Prefix replaces T with ErrorRelic, the ERROR is added to
the player successfully, but the subsequent cast to T fails. The event never
reaches SetEventFinished(), which looks like a softlock.

Confirmed examples:
- LostWisp: RelicCmd.Obtain<LostWisp>() -> EVENT2 softlock.
- SunkenStatue: RelicCmd.Obtain<SwordOfStone>() -> EVENT2 softlock.
- DollRoom: RelicCmd.Obtain(RelicModel, Player) -> EVENT2 works.

EVENT3 behavior
---------------
- Direct/non-generic relic obtains during EventOption.OnChosen:
  convert to ERROR.
- Generic RelicCmd.Obtain<T> during EventOption.OnChosen:
  remain vanilla so the required T return contract is preserved.
- Merchant / Chest / Elite / Ancient / Neow stable paths are not redesigned.
- EVENT1 display-layer patch remains removed.

This is a compatibility build: no generic event should softlock merely because
its T was replaced with ErrorRelic.

Test first
----------
1. LostWisp CLAIM:
   expected: vanilla LostWisp relic, event MUST finish normally.
2. SunkenStatue GRAB_SWORD:
   expected: vanilla SwordOfStone relic, event MUST finish normally.
3. DollRoom relic choice:
   expected: ERROR relic, event MUST finish normally.
4. Merchant / Chest / Elite / Ancient / Neow:
   quick regression check.

Build only. No asset/PCK changes.
